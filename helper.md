# Helper.md: контур C на 2026-10-09

Журнал фактического состояния `mcp-1C-v2`. Не план Docker и не старые правила пакета СКД.

Ветка обзора: `review/helper-2026-10-09`. База `main` на `f0b405a`.

## 1. Схема

Запрос клиента в свободной форме → модель → MCP → текст BSL.

Хост до модели метаданные не ищет и запрос в базе не исполняет. Текст пишет модель. Хост проверяет форму и имена по карточке. Готовый запрос шаблоном не подставляется.

Инструменты, которые модель вызывает сама:

1. `resolve_phrase` — развилка из `data/phrases.json`. При `need_clarification` BSL не пишется.
2. `search_metadata` — поиск по словам, не по всей фразе как одной подстроке.
3. `get_metadata_structure` — карточка: реквизиты, типы, синонимы, `query_name`, связи, виртуальные таблицы.
4. `check_query` — черновик против карточки и `check_join`.
5. `list_metadata_categories` — обзор категорий, необязателен.

Если `check_query` вернул успех, этот текст сразу идёт на доску. Ход `review_bsl` его не переписывает: так `БИНИИН` не подменяется смешанной латиницей. Если проверка не прошла, отказ возвращается модели.

Доска: `python app.py`, порт 8000. Ключ в `secrets.env`. Журнал ходов на странице. Токены запроса и сессии в ответе `/generate`. Файл `data/logs/board.jsonl`: время, укороченный запрос, статус, модель, usage. Ключ API не пишется. Каталог `data/logs/` в git не входит.

## 2. Что уже закрыто

- Схема модель → MCP соблюдается с `57016ef`: BSL до карточки не принимается.
- Одна выборка без пакета. `ПОМЕСТИТЬ` до `ВЫБРАТЬ` и хвостовой `УНИЧТОЖИТЬ` хост отклоняет (`4eb74ee`).
- Остатки: `РегистрНакопления.АВТоварыНаСкладах.Остатки(&ДатаОстатков, ) КАК Остатки`.
- Выбытие: уточнение, документ `АВВыбытиеАктивов`, реализация юрлицу или обороты `РегистрНакопления.АВАктивы`. Остатки этого регистра за выбытие не предлагаются.
- Соединение: одно левое, `ПО` из типа ссылки. Для юрлиц и договоров рабочий текст: `Справочник.АВЮридическиеЛица` ЛЕВОЕ СОЕДИНЕНИЕ `Справочник.АВДоговора` ПО `АВЮридическиеЛица.Договор = АВДоговора.Ссылка`, поля `БИНИИН` и `Наименование`.
- Парсер XML пишет типы, синонимы и `ИмяВЗапросе`.
- Проверка без LLM: `python -m unittest tests.test_tool_loop tests.test_phrases tests.test_balances tests.test_metadata_json tests.test_parser_types`.

## 3. Обзор кода 2026-10-09

Исправлено на этой ветке:

- В `openai_tools()` не было `get_metadata_structure`. Промпт инструмент требовал, список для модели его не объявлял. Живые прогоны вызывали его только если модель угадывала имя. Инструмент добавлен в список доски.
- В `choice_made` условие «выбытие активов и не реализация» из-за приоритета `or`/`and` срабатывало и на фразу с реализацией. Скобки расставлены.

Недоработки, код не менялся:

- Ранний выход после успешного `check_query` не прогоняет `check_bsl`. Пакет с `ПОМЕСТИТЬ` до `ВЫБРАТЬ` может пройти, если `check_query` его не увидел.
- `check_bsl` смотрит последнюю успешную карточку, не все открытые.
- Отказ всё ещё может продублировать причину: «после ИЗ пиши …» и «имя категории во множественном числе».
- Поиск «выбывшие активы» без `resolve_phrase` легко берёт опись или справочник `АВАктивы`, не документ выбытия.
- Правое соединение, объединение, пакет ВТ и СКД не собираются. Промпт их не требует, пока клиент явно не попросил.
- Вставка текста в 1С и Docker не сделаны. В `helper.md` до этой даты Docker был записан как текущая архитектура — это не так.
- Старые правила пакета, `ИНДЕКСИРОВАТЬ ПО`, `ЕСТЬNULL` и фигурных скобок СКД из промпта сняты. Матрица ниже их больше не считает обязательными.
